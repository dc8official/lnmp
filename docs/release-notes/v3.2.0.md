# Release Notes: LNMP v3.2.0

**Release Tag**: `v3.2.0`  
**Target Architecture**: Next-Generation Hybrid Active/Passive Monitoring & UI Modernization  
**Release Date**: September 24, 2026  

---

## Executive Summary

LNMP `v3.2.0` marks a landmark evolution in the platform's history, transforming LNMP from an active ICMP/probe-based monitoring system into a **high-throughput, hybrid active and passive telemetry engine**. By integrating line-rate NetFlow v5/v9 and IPFIX flow ingestion alongside our microsecond-accurate synthetic probes and the battle-tested $7 \times 24$ (168-hour) adaptive baseline model, LNMP delivers complete visibility into both endpoint reachability and network traffic flows.

In addition to deep passive telemetry, `v3.2.0` introduces a completely modernized, WCAG 2.2 AA compliant operator interface, decoupled cryptographic key management, horizontal multi-process worker partitioning, Redis Streams durable event pipelines, and zero-downtime database hypertable policies.

---

## What's New in v3.2.0

### 1. Hybrid Active/Passive Telemetry Core
* **NetFlow v5, NetFlow v9, and IPFIX Ingestion**: Native UDP listeners on ports `2055` and `4739` capable of processing 50,000+ packets/sec with zero packet drop.
* **Flow Aggregator & Two-Tier In-Memory Accumulator**: Aggregates raw flows into 1-minute rollup buckets with atomic flush to TimescaleDB hypertables.
* **Correlated Incident View**: Dual-axis latency and bandwidth charting on endpoint detail pages, allowing immediate identification of latency spikes caused by link saturation.
* **Multi-IP Exporter Grid**: Automatically maps physical router interfaces, loopback addresses, and secondary IPs to monitored endpoints.

### 2. Modernized Network Operator Experience
* **WCAG 2.2 AA Compliant Status Badges**: High-contrast geometric badges (`UP`, `DOWN`, `DEGRADED`, `PENDING`) with real-time pending confirmation cycle counters.
* **DOM Row Recycling (`VirtualScroller`)**: High-performance scrolling container supporting 10,000+ endpoints without DOM bloat or memory degradation.
* **Diagnostic Inspector Drawer**: Slide-out drawer with microsecond sparklines, 168-hour baseline corridors, and 1-click diagnostic traceroute triggering.
* **Telemetry Slice Export Popover**: Instant client-side CSV and JSON export for custom time windows and forensic analysis.
* **Modular Settings Architecture**: Refactored monolithic settings into modular subcomponents (`SettingsAlerts`, `SettingsFlow`, `SettingsSecurity`, `SettingsUsers`) with dirty-state tracking and unsaved changes navigation guards.

### 3. Enterprise Hardening & Security
* **Decoupled Cryptographic Keys (STAB-09 / SEC-04)**: Independent keys for JWT signing (`NETMON_JWT_SECRET`) and credential encryption (`NETMON_CRYPTO_KEY`), with fallback rotation keys (`NETMON_FALLBACK_CRYPTO_KEYS`) for zero-downtime key rotation.
* **Distributed Account Lockout (SEC-03)**: Redis-accelerated brute-force prevention tracking failed attempts across distributed API worker processes.
* **Durable Redis Streams (STAB-06 / ARCH-01)**: Guaranteed event delivery and replay with consumer group checkpointing on `stream:lnmp:events`.
* **Multi-Process Engine Partitioning (STAB-07 / PERF-01)**: Horizontal scaling of monitoring daemons across multiple CPU cores via `NETMON_ENGINE_WORKER_ID` and `NETMON_ENGINE_NUM_WORKERS`.
* **Deep Health Probes (STAB-08 / OPS-01)**: Independent `/health/liveness` and `/health/readiness` endpoints with systemd `WatchdogSec=30` support.

### 4. Database & Storage Architecture
* **TimescaleDB Continuous Baselines (0009)**: Rebuilt continuous aggregates using `time_bucket('1 hour', start_time)` with transparent view compatibility preserving the 168-hour adaptive baseline lookup array.
* **Hypertable Retention Policies (0010)**: Automated data lifecycle with 730-day retention for probe events and 90-day retention for minute rollups.

## Upgrade Guide from v3.1.x

1. **Run Database Migrations**:
   ```bash
   alembic upgrade head
   ```
2. **Review Environment Configuration**:
   ```bash
   # Optional: Configure dedicated keys
   export NETMON_JWT_SECRET="<jwt-secret-min-32-chars>"
   export NETMON_CRYPTO_KEY="<crypto-secret-min-32-chars>"
   ```
3. **Restart Daemons**:
   ```bash
   sudo systemctl restart netmon-api netmon-engine netmon-flowd
   ```
