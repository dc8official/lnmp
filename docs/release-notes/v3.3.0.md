# Release Notes: LNMP v3.3.0

**Release Tag**: `v3.3.0`  
**Target Architecture**: Flow Exporter Specialization & Per-Interface Telemetry (ManageEngine Benchmark)  
**Release Date**: September 25, 2026  

---

## Executive Summary

LNMP `v3.3.0` elevates the platform's network flow ingestion engine to enterprise parity with industry-standard flow analyzers like ManageEngine NetFlow Analyzer. This release introduces first-class support for **Dedicated Flow Exporters** (`FLOW_EXPORTER` device role) with passive telemetry isolation, per-interface directional throughput accounting (`flow_interface_minute_rollups`), live link utilization monitoring against provisioned line speeds, 1-click exporter enrollment from unmapped stream banners, interactive interface isolation on the Bandwidth dashboard, and fleet SLA protection.

Existing deployments upgrade with zero historical data loss, automatic legacy alias coercion, and zero disruption to active monitoring tracks.

---

## What's New in v3.3.0

### 1. Dedicated Flow Exporter Roles & Passive Monitoring
* **`device_role` Hierarchy**: Endpoints can now be designated as `FLOW_EXPORTER`, `STANDARD`, `EDGE_ROUTER`, or `CORE_SWITCH` with strict database check constraints (`ck_endpoints_device_role`).
* **Passive Telemetry Neutralization**: Flow routers enrolled as `FLOW_EXPORTER` automatically operate with synthetic ping polling disabled (`monitoring_enabled=False`), operational status reported as `PASSIVE` with concentric geometric indicators, and 100% health score to protect executive SLA reports from false downtime penalties.
* **Smart UI Perspective Defaulting**: Visiting an endpoint with `FLOW_EXPORTER` role automatically opens the Bandwidth / Flow Telemetry tab as primary, presenting an informational banner on the ICMP tab explaining passive telemetry mode.

### 2. ManageEngine-Style Interface Telemetry Grid
* **Per-Interface TimescaleDB Hypertables**: Added `flow_interface_minute_rollups` with composite primary key `(bucket, exporter_id, interface_idx)`, index `idx_flow_if_rollups_exp_if_bucket`, and a 7-day retention policy.
* **Directional Attribution & Bounds Guarding**: Ingress bytes/packets are attributed strictly to ingress interfaces (`in_if`), egress bytes/packets to egress interfaces (`out_if`), and flow counts to both. Sentinel UUIDs (`00000000-0000-0000-0000-000000000000`) and invalid IPFIX interface indices (0 or negative) are strictly rejected.
* **Live Throughput & Link Utilization**: `GET /api/v1/bandwidth/interfaces` computes real-time ingress/egress bps and link saturation percentages against provisioned capacities with color-coded warning/critical thresholds.
* **Configurable Speeds & Presets**: Built-in speed presets (10 Mbps, 100 Mbps, 1 Gbps, 10 Gbps, 40 Gbps, 100 Gbps, Custom) configured via `PUT /api/v1/bandwidth/endpoints/{id}/interfaces` and accessible modal dialog in `EndpointDetailView.vue`.

### 3. Exporter Forensics & 1-Click Enrollment
* **Scope Switcher on Bandwidth Dashboard**: Effortlessly switch between `🌐 Fleet Aggregate` and individual router scopes (`🟢 Router-01 (10.0.0.1)`). Selecting a router dynamically surfaces its active interface grid and scopes Top Talkers queries to router transit.
* **Click-to-Isolate Interface Throughput**: Clicking any interface row in the telemetry table isolates its traffic curve on the aggregate time-series chart with instant clear buttons.
* **1-Click Exporter Enrollment Modal**: The unmapped exporter banner now provides a `[ + Enroll Exporter ]` modal calling `POST /api/v1/bandwidth/exporters/enroll` to immediately register unknown IP streams as managed flow exporters without manual endpoint creation.
* **Sliding Unmatched Cardinality Shield**: Unmatched router IPs are tracked in a 24-hour Redis sorted set (`flow:unmatched:zset`) capped at 1,000 unique candidates to eliminate memory exhaustion.

### 4. Zero-Loss Backward Compatibility
* **Polymorphic Alias Validator**: Existing database records containing legacy string aliases (`{"1": "Gi0/0"}`) are transparently coerced to structured configuration objects (`{"name": "Gi0/0", "speed_mbps": 1000}`) preventing schema validation errors.
* **TimescaleDB Extension Guard**: Database migration `0012_v3_3_flow_interface_telemetry.py` dynamically detects whether the TimescaleDB extension is present before attempting hypertable partition commands, running cleanly on vanilla PostgreSQL in test environments.

### 5. Enterprise PDF Reporting Engine & Document Immutability
* **Three Dedicated Audit Templates**:
  * **Template A (Availability & SLA Performance)**: Multi-endpoint availability matrix, objective uptime percentages, cumulative downtime durations, packet loss, average latency (RTT), and recorded outage incident ledger with Root Cause Analysis (RCA).
  * **Template B (Bandwidth & Interface Capacity)**: Exporter routers summary, per-interface directional bandwidth accounting, line-speed capacity utilization with color-coded warning/critical thresholds, and cross-router forensic top conversations.
  * **Template C (Executive Master Audit Dossier)**: 4-part synthesis dossier consolidating availability, outage ledgers with RCA, interface capacity metrics, and top transit conversations.
* **Air-Gapped Rendering Security**: Powered by WeasyPrint with a custom `secure_url_fetcher` that disallows all external network access (`http://`, `https://`, `ftp://`) to eliminate SSRF and data exfiltration, while strictly confining local disk access to whitelisted template and asset roots.
* **Document Immutability**: Enforces read-only protection under the hood using standard PDF permission encryption (`pypdf` with `UserAccessPermissions.PRINT | UserAccessPermissions.PRINT_TO_REPRESENTATION`), disabling content extraction, modification, and form alteration while keeping visual pages clean and free of cryptographic clutter (SHA-256 delivered via HTTP header `X-Report-SHA256`).
* **Interactive Export Modal on `/reports`**: Operators and Admins can launch an interactive modal dialog to select report templates, scope (all endpoints or individual target checklists), time horizons (24h, 7d, 30d, custom), and optional Root Cause Analysis (RCA) diagnostics.

### 6. Organization Profile & Corporate Report Branding
* **Admin Branding Governance (`/settings` tab: 🏢 Organization & Branding)**: Administrators can configure corporate identity settings including Company Name, Department / Operations Unit, Report Footer Disclaimer, and upload corporate logos (PNG, JPG, SVG, max 2MB Base64 data URI).
* **Dynamic Report Compilation**: Corporate branding headers and running confidentiality footers are automatically populated into all compiled PDF reports with graceful enterprise defaults.

### 7. Direct Interface Alias & Speed Configuration on `/bandwidth`
* **In-Context Interface Editing**: Administrators can configure interface names/aliases and line speed presets (10 Mbps, 100 Mbps, 1 Gbps, 10 Gbps, 40 Gbps, 100 Gbps, or custom Mbps) directly from the Bandwidth interface telemetry table via `[ ⚙ Configure Interfaces ]` and row-level quick-edit `✎` buttons.

## Upgrade Guide to v3.3.0

To upgrade from v3.2.0 or v3.1.x:

```bash
cd /opt/netmon/noop
sudo ./deploy/upgrade.sh
```

The upgrade script automatically checks and installs required system packages for PDF rendering (`libpango-1.0-0`, `libharfbuzz0b`, `libharfbuzz-subset0`, `libpangoft2-1.0-0`).

Or manually:
```bash
# 1. Install system rendering libraries
sudo apt-get update && sudo apt-get install -y libpango-1.0-0 libharfbuzz0b libharfbuzz-subset0 libpangoft2-1.0-0

# 2. Update Python dependencies
.venv/bin/pip install -r backend/requirements.txt

# 3. Apply database migration
alembic upgrade head

# 4. Build frontend assets
cd frontend && npm run build && cd ..

# 5. Restart system services
sudo systemctl restart netmon-api netmon-engine netmon-flowd
```
